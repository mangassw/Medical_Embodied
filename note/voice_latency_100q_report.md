# 100 题全链路耗时测量报告（2026-11-10）

## 测试条件

- 链路：真实语音链（网关 qwen-plus-latest + BM25 RAG + CosyVoice2 TRT fp16 + 播放）
- 输入方式：`/question_asr` 文本注入（等价于 ASR 识别完成后的起点；端点/ASR 时间另行分段见下）
- 100 题：23 道评测题 × 5 种问法变体（`questions_100.json`）
- 逐题串行：等每题播报完成（`/tts_session_finished`）再发下一题
- 埋点：`LATENCY_PROBE=1`（网关/TTS 内部阶段经 `/latency_event`）
- 结果文件：`tools/voice_regression/out/measure_detail.csv`（逐题）、`measure_summary.md`、`measure_rows.json`、`measure_events.jsonl`

## 结果总览（100/100 成功，0 超时；单位 ms）

| 阶段 | 中位 | P90 | 最大 | 最小 |
| --- | ---: | ---: | ---: | ---: |
| 网关接收→开始生成 [START] | 1444 | 3213 | 10040 | 348 |
| RAG 检索（BM25 进程内） | 1 | 4 | 22 | 0 |
| LLM 首包（含云端建连） | 1444 | 3213 | 10040 | 348 |
| LLM 生成（首 delta→DONE） | 836 | 1128 | 10950 | 0 |
| 首回答音频起播（注入起算） | 3470 | 6055 | 12772 | 1219 |
| TTS 合成总耗时（3 单元合计） | 8434 | 16240 | 22344 | 2663 |
| 端到端（注入→播报完成） | 18890 | 24816 | 32901 | 8014 |

## 关键结论

1. **端到端 18.9s 中约 15s 是回答音频的播放时长**（内容本身），真正的“反应等待”是首回答音频前的 ~3.5s：
   端点（真实语音 0.55~1.2s）+ 网关（含云端建连 1.44s 中位）+ LLM 首包 + 首句合成（流式首块）。
2. **最大波动源是云端建连/响应头等待**（中位 1.44s，P90 3.2s，最大 10s）与 LLM 生成抖动（有 11s 离群）。
3. RAG（BM25）稳定在毫秒级，不是瓶颈。

## 已实施的优化（本轮）

**[START] 提前发布**：网关在发起云端请求**之前**发布 `[START]`，TTS 的填充词“好的，”不再等待云端建连。

| 指标 | 优化前 | 优化后（实测） |
| --- | ---: | ---: |
| 问题→[START] | 中位 1444ms | **3ms** |
| 问题→填充词起播 | ~1.4–1.7s | **152ms** |
| 问题→正式回答首音 | 3.5s 中位 | 3.5s（不变，取决于 LLM+首句合成） |

## 后续可优化项（按性价比）

1. 云端建连等待（P90 3.2s / 最大 10s）：可加 HTTP 连接预热（唤醒时预先建立连接）或双通道自动切换
2. 首句合成（~1.5s）：可尝试缩短首句模板（目前已限制 ≤8 字）
3. LLM 生成离群（最大 11s）：重试/降级策略
